Drive keys

Drive files are encrypted with keys made from two server keys: the root MEK and a sub-MEK. The server keeps them (so it can open Drive files); losing them loses every Drive file. Generate them here (recommended), or enter keys you made yourself. After you log in, download the key kit (Admin → Security → Keys) and store it offline.

The server proposes a root MEK and a first sub-MEK (it needs the setup token above). They are shown here, hidden until you choose Show. Nothing is stored until you choose “Use these” and create the owner; the server forgets a proposal after 10 minutes.

Make each key out of band, 32 random bytes as base64 or hex, for example openssl rand -base64 32 — or in PowerShell [Convert]::ToBase64String([Security.Cryptography.RandomNumberGenerator]::GetBytes(32)) (not Get-Random, which is not a secure generator) — or take them from a hardware security module or a secrets manager. The two keys must differ. Keep a copy in a secrets manager.

The Drive keys that exist are kept: recovering the owner account never changes them.

Secret generator

Random values generated locally in this browser (never sent anywhere). Store each as a Worker secret, e.g. wrangler secret put SIG, or generate them yourself with openssl rand -hex 32. After setup, delete AUTHN.
